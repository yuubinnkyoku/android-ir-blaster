# DP-700SH investigation evidence — 2026-09-24 01:47 JST

## New confirmed evidence: DP-70SH `TH180700.ver` contains a gzip member

The archived official FUJIFILM DP-70SH firmware `TH180700.ver` was retrieved as raw `application/octet-stream` data from the Wayback Machine capture dated 2016-06-23 11:31:10.

Source binary:
- Original URL: `http://download.fujifilm.co.jp/pub/tools/dp70sh/TH180700.ver`
- Wayback raw capture: `https://web.archive.org/web/20160623113110id_/http://download.fujifilm.co.jp/pub/tools/dp70sh/TH180700.ver`

### Confirmed

In the binary, immediately after the firmware region-name table (`BOOT`, `NVRAM`, `NVRAM_2`, `ROMTAB`, `STRTAB`, `FIRMWARE`, `VERSION`, `CHECKSUM`), the byte sequence represented by the raw capture includes `1f 8b 08`, the gzip magic (`1f 8b`) followed by compression method 8 (DEFLATE).

This upgrades the previous observation based on strings such as `gz_size %x` and `inflated`: the file does not merely contain gzip-related code; at least one actual gzip member is embedded in the official firmware image.

The same raw binary also reconfirms nearby updater/debug strings already observed:
- `SHARP_PF100_PLATFORM`
- `NEW SERIAL FLASH`
- `gz_size %x`
- `fwz_index`
- `inflated`
- `FCK ROM -> MAIN`
- `ATMEL`
- `MXIC`
- `erase %x`
- build-like timestamp `13:21:49 Apr 23 2009`

### Interpretation / hypothesis (not confirmed for DP-700SH)

The DP-70SH update image appears to combine executable/updater material, a region table, and one or more gzip-compressed payloads. This gives a concrete signature to test if `TH34_dpf.pkg` (DP-700SH) is recovered: search for gzip members (`1f 8b 08`) together with `SHARP_PF100_PLATFORM` and the region names above, then compare decompressed contents and layout.

This does **not** prove that DP-700SH uses the same container, PF100 platform, SoC, or OS. It only establishes the gzip payload structure for the directly recovered DP-70SH official firmware.
