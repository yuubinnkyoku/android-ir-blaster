# DP-700SH 調査ログ — 2026-08-20 01:48 JST以降

## JVCルートの発見

### DP-7VとVictor/JVC TVリモコンの衝突

価格.comのFUJIFILM DP-7Vクチコミ（2010-05-28）に、DP-7Vが「ビクター製のテレビのリモコンのON/OFFスイッチ」とかぶって反応するという実機報告がある。

Source:
- https://bbs.kakaku.com/bbs/K0000060109/

これはDP-700SHそのものの証拠ではないが、同時期FUJIFILMデジタルフォトフレームでJVC TV信号との衝突が実在したことを示す。

### JVC TVのdevice/functionを絞り込み

JP1/JVC資料では標準JVC protocolは8-bit device + 8-bit function (`D:8,F:8`)。

古いJVC TVでは主要機能がdevice 3にあり、Power toggleはOBC 23。別のJVC RM-C1900S情報でもdevice=3系のボタン一覧が確認できる。

Sources:
- https://hifi-remote.com/wiki/index.php/JVC
- https://www.hifi-remote.com/forums/viewtopic.php?t=5446
- https://www.hifi-remote.com/forums/viewtopic.php?t=14737

Power toggle:
- device = 3 = `0x03`
- OBC/function = 23 = `0x17`

### android-ir-blasterへの入力値

repoの `lib/ir/protocols/jvc.dart` は4桁hexを2 byteに分け、各byteをLSB-firstで送る。

したがって論理値device=3/function=23は app入力 **`0317`**。

古いLIRC captureの表記では、bit reversal済みの見かけ上 `C0E8` になる場合があるが、このappへ入力するのは `0317`。途中で一度C0E8をapp入力候補と解釈したが、これは表現層の取り違えなので訂正済み。

### device 31は優先しない

古いJP1投稿にJVC TV device 31という言及があるが、同じ議論で専門家が再確認し、JVC:3中心・補助機能に15/35等という例を示している。31は現時点では根拠が弱いので優先しない。

Source:
- https://www.hifi-remote.com/forums/viewtopic.php?t=6858

### 実機での次手

Sharp 13-bitが空振りなら:

1. JVC `0317` を単発
2. 反応しなければ JVC / Known prefix `03` / 残り1 byte総当たり
3. 候補数は256
4. それも外れた後に他protocol/DB/Kaseikyoを検討

## DP-7VはDP-700SHと別ソフト系統らしい

DP-7Vには2010-07-30公開のfirmware **1.2.30** が存在する。価格.comの発売初期個体では1.2.2.0 / 1.2.2.5という出荷バージョン差の報告もある。

Sources:
- https://dc.watch.impress.co.jp/docs/news/385194.html
- https://bbs.kakaku.com/bbs/K0000060109/

一方:
- DP-70SH公開更新: 1.04.00
- DP-701SH/DP-801SH公開更新: 1.04.07

Sources:
- https://dc.watch.impress.co.jp/cda/accessories/2009/04/01/10602.html
- https://dc.watch.impress.co.jp/docs/news/464018.html

このバージョン体系差から、DP-7VはDP-70SH/700SH/701SH系列とは別のソフトウェア/ODM系統である可能性がある。したがってJVC衝突はDP-700SHへの直接証拠ではなく、低コストで検証可能な仮説としてのみ使う。
